# H3 / ComfyUI 逐镜视频规划使用说明

## 功能入口

在创作页的分镜区开启 **AI逐镜推荐**，随后生成分镜。经典分镜与通用分镜使用同一套规划能力；文字模型选择仍只决定分镜文本的生成模型。

每张分镜卡分别显示推荐、当前选择、手动锁定、来源、执行状态和采用版本。推荐仅来自受信任的脚本注册目录，不会自动下载工作流或把未知模型当成已支持模型。

对已有分镜使用 **更新本集推荐（保留镜头与手动锁）**，不会重新生成分镜或清空视频。当前按钮采用本地规则重推荐，推荐来源明确标成规则；不会自动判定跨集连续镜头。API 另支持显式 `strategy: ai`，通过文字模型重推荐；AI 失败或返回不完整内容时保留原数据，不悄悄换成规则推荐。分镜生成过程中的推荐则随 AI 返回的分镜一起产生。

## 单镜生成与手动选择

1. 在分镜卡点击 **手动选择 / 锁定**，选择具体模型 ID。
2. 单段和首段模型不需要续接来源；续接模型必须选择同剧内的具体版本或规划镜头修订。
3. 点击 **预览本镜计划**，核对模型、提示词、参考输入、来源及阻塞原因。
4. 点击 **运行计划（提交 GPU）** 后才会提交视频生成任务。
5. 完成后打开 **版本 / 采用**，预览视频并明确采用。新生成的版本不会覆盖已采用的视频。

手动锁保留当前选择，不会因更新推荐或改变全局默认视频模型而被覆盖。镜头内容或来源变化后，锁定方案也必须重新确认；锁定不绕过输入校验。**明确跟随推荐** 会明确解除手动选择并使用当前有效推荐。

生成被中断、JSON 截断修复或缺少推荐时，不会激活可执行选择。草稿需要完成生成或重新推荐后才能执行。重新生成分镜建立新的 ID，不会仅按相同镜号继承上一轮的手动锁或视频选择。

## 第二集与连续镜头

“下一集”“相同人物”“更长时长”本身不会触发续接。只有表达同一连续镜头意图、提示词没有切镜要求且来源兼容时，AI 才能推荐续接。

例如希望第二集首镜接续第一集末镜：先让第一集来源产生可验证的 latent；在第二集首镜手动选择相容的续接模型，再选择第一集的**具体版本及尾段**。同剧跨集可选，跨剧不可选。来源不会隐式切换成之后生成的最新版本。

常用组合由注册目录决定：

- `h3-long-drama-first` → `h3-long-drama-continue`
- `h3-long-action-first` → `h3-long-action-continue`
- `h3-pv-first` → `h3-pv-continue`

普通单段可选择 `h3-standard`、`h3-drama`、`h3-action`。需要当前页面未提供的音频或视频输入的目录项会显示不可用。

跨镜/跨集来源只提供续接状态，**不会把来源视频拼进当前分镜或本集**。同一分镜需要保留旧片段并追加新片段时，必须选择相容的旧版本并使用明确的 **预览同卡追加** 操作；追加后的版本有独立身份和完整成员列表。

尚未生成的来源可绑定到本次有限计划里的具体前序节点。不在本次计划内的来源保持等待，不会自动去生成前一集或其他未选镜头。没有可用 latent 的旧普通视频不能仅凭视频 URL 作为续接来源。

## 批量、恢复与采用

批量和一键流程遇到已规划镜头，会进入有限计划预览。预览只固定这一次明确选择的目标与输入；只有就绪节点可提交，失败或阻塞节点不会被当成成功。关闭预览对话框不会取消已提交任务。

每次提交先保存执行记录，之后才调用桥接服务。提交响应丢失且无法确定是否受理时，状态为 **提交结果未知**：只刷新原计划，不自动重新提交。已获得任务 ID 的任务可以恢复查询，仍使用原先冻结的连接；不会改用新的默认连接。后端重启会恢复已启动计划的已知任务状态。

预览不是采用。生成完成也不是采用。需要逐镜明确选择版本或历史视频，整集合成和“上一镜尾帧”才会使用该选择。采用操作使用修订号防止并发覆盖；遇到冲突先刷新，再按当前状态选择。

合成整集前每镜必须都有明确可用的视频。缺镜、下载失败、损坏媒体或后处理失败会使本次合成失败，不会用第一段或部分视频冒充整集。字幕和旁白按媒体实测时长排布；尾帧取已采用媒体的最后显示帧。

## ComfyUI 连接与 latent 输出目录

在现有 AI 配置里使用 **原生 ComfyUI** 视频连接，并登记要使用的具体模型 ID。有限计划按每个具体模型寻找支持它的本地连接，不能只把全局默认模型当成通用连接。连接地址指向原生 ComfyUI；继续复用项目现有受管桥接器，不需要另起桥接实例。

latent 来源核验优先使用精确任务/原生 prompt 历史和注册的保存节点；只接受该任务独占输出前缀，不会搜索最新文件。若历史没有暴露 latent 文件，且 ComfyUI 与后端能访问同一文件系统，可配置受信任的 ComfyUI **output 根目录**。

在 `backend-node/configs/config.yaml` 增加或合并以下配置（路径必须替换成本机实际目录）：

```yaml
comfyui:
  output_root: 'D:/ComfyUI/output'
```

也可在具体 AI 配置的 `settings` JSON 中设置 `comfyui_output_root`，该连接的设置优先于全局配置。请合并已有 settings，不覆盖其他选项。当前 AI 配置表单没有新增专用目录输入框；配置文件方式最直接。不要把模型目录、latent 文件本身或后端 storage 目录填成 output 根目录。

连接和输出目录在预览时冻结。配置改变后，已存在的计划保留旧快照；需要使用新配置时重新预览。没有共享目录但原生 `/history` 与 `/view` 能提供精确文件时，可以通过 HTTP 验证；两种方式均无法验证时，已生成视频仍可播放和采用，但续接被阻止。

输出文件会校验来源、规范路径、任务独占前缀、safetensors 头与张量布局、文件长度。**结构校验通过不等于本机 GPU 已成功加载，也不证明张量语义兼容。** 界面与 API 分别展示这两个状态。本次实现没有进行真实 GPU 生成或 latent 加载验收。

## 常见阻塞

- 草稿 / 推荐缺失：完成分镜生成或更新推荐。
- 内容、道具关联或来源修订已变化：刷新后重新推荐或确认手动方案，并重新预览。
- 来源不在本次计划：选择已完成的确切版本，或把前序镜头纳入同一次有限计划。
- 未配置匹配模型的原生连接：在 AI 配置中检查具体模型 ID、协议与地址。
- latent 缺失、多个候选、结构损坏或路径越界：保留可播放版本，修复真实产物或配置后重新选择有效来源；不能跳过校验。
- 提交结果未知：保留原计划和任务标识，不盲目再发生成请求。

## 接入与验证

新增表由正常后端启动的 schema migration 创建。已有运行进程不会因前端构建而自动加载后端路由；更新后应通过原有启动方式让后端加载新代码，再刷新页面。不要为此启动第二套同端口服务。

检查 `GET /api/v1/video-planning/capabilities` 应返回项目正常响应封装，包含目录版本和 `items`；若返回 API endpoint not found，当前进程尚未加载本次路由。

开发回归：在 `backend-node`、`frontweb` 各运行 `node --test test/*.test.js`，前端运行 `npm run build`。本机 SQLite 原生模块对应 Node 22，请使用 `C:/nvm4w/nodejs/node.exe`。Windows PowerShell 若拒绝 npm.ps1，构建可使用 `npm.cmd run build`。

接口和数据语义见 [实现约定](video-planning-implementation-contract.md)。注册目录只表示已登记；真实模型文件、自定义节点、显存、GPU 运行及具体工作流的画面质量仍需本机实际验收。
