参考图实测：模型支持，当前应用调用未采用

配置：Sub2Api 分镜图；模型：gpt-image-2.5-sunburst。以下均为真实上游调用，离线捕获只用于事先校验图片字节。

结论：该模型能够真正读取参考图。当前 /images/generations 加 JSON image 字段的方式未让参考图生效；标准 /images/edits 加 multipart 图片文件则生效。此报告验证调用方式，尚未修改业务生图接口。

实验传输方式图片输入 token观察
无图对照JSON，仅文字0生成场景；提供有效对照
主角参考图当前 JSON image0生成的人物外观偏离角色图
随机标记参考图当前 JSON image0未复现输入形状、配色和编号 B9FE6F
标准图片编辑multipart image 文件1024复现输入形状、配色及编号 827722

直观证据

随机编号只画在输入图片中，提示词没有编号、具体颜色、形状及其位置。两个标记实验使用相同提示词，分别生成新的随机编号，避免从文本中猜中答案。

主角参考图对照

左侧是项目实际角色图；右侧为当前调用方式的输出。有效请求已验证传入图片的字节哈希与原图一致。

复现方式

从仓库的 backend-node 目录执行。默认读取当前分镜图配置和剧目 1 的徐牧角色；通过 --drama、--character 可以指定其他对象。

# 只检查配置，不调用模型
& 'C:\nvm4w\nodejs\node.exe' tools/check-storyboard-references.js

# 捕获并校验实际应用链路，零上游调用
& 'C:\nvm4w\nodejs\node.exe' tools/check-storyboard-references.js --capture-only

# 实测无图、主角带图、随机标记图，共 3 次调用
& 'C:\nvm4w\nodejs\node.exe' tools/check-storyboard-references.js --run

# 标准 multipart 编辑接口对照，仅 1 次调用
& 'C:\nvm4w\nodejs\node.exe' tools/check-storyboard-references.js --run --edits-only

实验边界与排除项

共发出 6 次上游请求：首轮两次带图测试因脚本把预编码图片误转为 URL 而排除；保留有效无图对照，修正后重测两次带图，再补充一次标准编辑对照。正式结论只使用 4 次有效实验。每项有效带图实验均在转发前校验图片字节；随机标记不会出现在提示词中。数据库以只读方式打开，应用链路使用内存配置副本，未写入业务生成记录；凭据仅在内存中使用，未保存到报告。

每个有效带图用例仅测一次；当前证据能确认本配置下的接口行为和模型读取图片能力，不能保证所有模型、接口或镜头中的人物一致性。token 用量由上游报告，输出复现图片内随机编号提供了独立视觉证据。
